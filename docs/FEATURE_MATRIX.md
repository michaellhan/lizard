# LIZARD feature matrix

Status as of 2026-11-03 (Lizard grades updated for the Phase 0 Study work, the Phase 1 Practice page and drills, the Phase 4 range builder, the Phase 5 saved spots, drills and ranges, backup and the classic import, the Phase 3 flop reports, and the first part of Phase 2, Analyze's import, `docs/PROGRESS.md`). This compares LIZARD with the public feature set of GTO Wizard, one row per feature. Each row has two grades:

- **Engine / classic.** What the bundled solver and its own web app (the "classic" app, `solver/gto/static/`, served at `/gto-solver/`) can do today.
- **Lizard UI.** What the new React app (`web/src/`) does today.

The solver is a snapshot of michaellhan/gto-solver at 9b907bd6, in `solver/`. Paths below are relative to the repository root.

## How this was graded

- Lizard grades come from reading the code only. Nothing was built, run or solved for this pass, because two long library builds were using the machine. A grade of WORKING for Lizard means the code path is complete and has unit tests. It does not mean it was clicked through in a browser.
- Classic grades come from reading the code and tests, and from the status reviews in `docs/research/07a`, `07b` and `07c`. Where my grade is lower than those reviews, the Notes say so and why.
- The GTO Wizard column is one short neutral phrase from public sources, summarised in `docs/research/02-gtowizard-inventory.md` §3. It is not a claim about how their product works inside.

In short, the engine covers most of the feature list, often in part. Lizard's React UI so far covers Study (with a range builder that scores a painted strategy), Practice (full hands and drills), flop reports from the library, Analyze (hand histories kept in the browser and replayed, each decision opening in Study; preflop decisions graded against the charts and flop decisions against the library, with leaks, frequencies and CSV/JSON export; turns and rivers not graded), a range editor, the library view, a Saved page (spots saved from Study, drills saved from Practice and Analyze, ranges saved from Ranges, backup and restore to a file), settings and engine diagnostics, and a Solve page that sets up a spot of your own (stacks, bet sizes, rake, ante or straddle, ranges entering the flop) and opens it in Study (node locks and automatic sizing are asked per hand in Study, not as range views), and a Tournaments page that sets up a tournament spot (the prizes left, each seat's stack, the other tables, KO, PKO or mystery bounties) and opens it in Study, answered in prize equity with the model on every badge and a panel of prize equity, bubble factors and bounties, with the same node in chip EV beside it on request (no table of every pair's bubble factor; satellites as a payout shape, approximate preflop).

## Facts that apply to many rows

- **Preflop numbers are mostly approximate.** The advice and Study use hand-written charts with no EV (`solver/gto/preflop.py:1-4`). A class-level preflop solver exists (`solver/gto/pf_study.py`, `pf_game.py`). It supports 2–6 players in the browser and 7 natively, equal stacks of 10–250bb, and no ICM. Its results are 2.4–3.0 points off published solves (`docs/research/03` §4). Classic Study can show it as a "Solver" source, and so can Lizard's Study (since 2026-11-03), labelled "Preflop solve (class-level model)".
- **Postflop solves are real, but in an abstracted game.** Heads-up uses DCFR with an exact best-response exploitability (`solver/gto/solver.py:2170-2196`). That number is measured in the abstract game: flop solves bucket the later streets, and the bet menu is small. Three-way spots are solved, 4-way spots use a reduced game, and 5+ players on the flop or turn use betting rules (`docs/research/03` §5, §7).
- **The presolved library is small.** It has 18 heads-up 6-max 100bb lines (9 on the newer river-dealt tree with turn files, 9 on the older tree) and 4 three-way spots on 185 flops each. Lizard's merged library at `/lizard-library/` also has two heads-up 2-max spots, copied from offline builds that are still running: `srp_sb_bb_2max` (378 flops so far, planned 1,755) and `lp_sb_bb_2max` (168 so far, planned 552), as of library commit `7c6995b`; `03329ce` republished the same flops with the 1,755 target in the summary. Heads-up flops not published yet are solved live. The classic `/gto-solver-library/` has no 2-max spots.
- **There are three grading scales in the classic app, and they disagree.**
  - Practice grades by frequency. Best, Good, Inaccuracy or Mistake; a frequency of 15% or more is fine (`solver/gto/static/practice.js:417-424`, `index.html:1543-1544`).
  - Drills grade by EV on five levels (`drills.js:154-169`).
  - The session analyzer uses mix thresholds of 0.15 and 0.03 (`session.js:528-532`).
- **What Lizard sends.** Its Study request carries players, stack, board, the line and `study: true` (`web/src/features/study/studyState.ts`, `studyRequest`). A spot set up on the Solve page adds `stacks`, `sizes`, `rake` and `rake_cap`, `ante`, `straddle` and `ranges` (`web/src/features/solve/setup.ts`, `setupRequest`); one set up on the Tournaments page adds `payouts`, `field` and `bounties` instead of rake (`web/src/features/tournaments/tournament.ts`, `tournamentRequest`). It sends no locks, automatic sizing or preflop-solve flag.
- **Two Lizard over-claims were found by this review and fixed the same day (2026-11-03).** The Practice route summary said "scored by EV loss" (`web/src/app/routes.ts:18`), and the placeholder page listed "EV-loss grading" for Practice. Classic Practice verdicts are frequency-based; only Drills use EV. Both now say so.

## Grades I was unsure of

- **Leak finding (classic, PARTIAL).** It could be APPROXIMATE, because preflop leaks are measured against hand-written charts.
- **Postflop trainer (classic, PARTIAL).** 07a says WORKING with few settings. I graded it lower for the missing filters and modes, and for the rough turn grading at Quick.

- **Node locking (classic, PARTIAL).** It is a tendency lock plus a best response, not a re-solve, so APPROXIMATE could be argued.
- **KO / PKO (classic, PARTIAL).** 07c says WORKING for the solved parts. The non-push/fold preflop part is heuristic.

- **Satellites (Lizard, APPROXIMATE).** Postflop is a prize-equity solve with flat payouts; preflop is the chip chart with a risk premium. PARTIAL could be argued.
