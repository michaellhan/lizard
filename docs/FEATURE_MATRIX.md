# LIZARD feature matrix

Status as of 2026-11-08 (Lizard grades updated for the Phase 0 Study work, the Phase 1 Practice page and drills, the Phase 4 range builder, the Phase 5 saved spots, drills and ranges, backup and the classic import, the Phase 3 flop reports, and the first part of Phase 2, Analyze's import, `docs/PROGRESS.md`). This compares LIZARD with the public feature set of GTO Wizard, one row per feature. Each row has two grades:

- **Engine / classic.** What the bundled solver and its own web app (the "classic" app, `solver/gto/static/`, at snapshot 1a14605e) can do today. It was served at `/gto-solver/`. `/gto-solver-classic/` is a frozen full copy, and the gto-solver project is reducing `/gto-solver/`, so that copy is where these features stay.
- **Lizard UI.** What the new React app (`web/src/`) does today.

The solver is a snapshot of michaellhan/gto-solver at 1a14605e, in `solver/` (re-pinned from 9b907bd6 on 2026-11-05). Paths below are relative to the repository root.

## How this was graded

- Lizard grades started from reading the code alone, while two long library builds were using the machine. Since then rows have been graded on what ran: the Notes say what was checked in a browser and when, and name the browser test. A row whose Notes cite only unit tests hasn't been clicked through. A grade of WORKING means the code path is complete and tested, for the scope its Notes state. By the owner's rule of 2026-11-08, a row is WORKING when its core job works end to end with tests and what's left is edge cases, polish, or environments not tried (Safari, Firefox, touch, a real screen reader, a phone's timing); heuristic user-visible numbers still aren't WORKING. Rows moved by that rule say so in their Notes, with what's left.
- Classic grades come from reading the code and tests, and from the status reviews in `docs/research/07a`, `07b` and `07c`. Where my grade is lower than those reviews, the Notes say so and why.
- The GTO Wizard column is one short neutral phrase from public sources, summarised in `docs/research/02-gtowizard-inventory.md` §3. It is not a claim about how their product works inside.

## Legend

| Grade | Meaning |
|---|---|
| WORKING | Works end to end in the code, with tests, and no core part is missing or heuristic. |
| PARTIAL | Works for a subset of cases, or a core part is missing. The Notes say which part. |

When I was unsure, I chose the lower grade. Rows marked **(unsure)** in Notes are listed again at the end.

In short, the engine covers most of the feature list, often in part. Lizard's React UI so far covers Study (with a range builder that scores a painted strategy), Practice (full hands and drills), flop reports from the library, Analyze (hand histories kept in the browser and replayed, each decision opening in Study; preflop decisions graded against the charts and flop decisions against the library, with leaks, frequencies and CSV/JSON export; turns and rivers not graded; your results and stats as played), a range editor, the library view, a Saved page (spots saved from Study, drills saved from Practice and Analyze, ranges saved from Ranges, backup and restore to a file), settings and engine diagnostics, and a Solve page that sets up a spot of your own (stacks, bet sizes, rake, ante or straddle, ranges entering the flop) and opens it in Study (node locks and automatic sizing are asked per hand in Study, not as range views), and a Tournaments page that sets up a tournament spot (the prizes left, each seat's stack, the other tables, KO, PKO or mystery bounties) and opens it in Study, answered in prize equity with the model on every badge and a panel of prize equity, bubble factors and bounties, with the same node in chip EV beside it on request (no table of every pair's bubble factor; satellites as a payout shape, approximate preflop).

## Facts that apply to many rows

- **The snapshot moved on 2026-11-05, and the grades were read before it.** `solver/` went from 9b907bd6 to 1a14605e. Line references into `solver/gto/advisor.py` and `solver/gto/static/*.js` were read at 9b907bd6 and may be some lines off. No Lizard grade changed. The classic app's work in that range (record a hand and review it once it's finished, your equity on a reviewed hand, Explain with AI on a reviewed decision) isn't in Lizard's UI, and the engine's `equity` request isn't sent by Lizard. An 8- or 9-handed pot that borrows a 6-max spot now reads it where it used to lose it (`scripts/engine/test_library_game.py`).
- **Preflop numbers are mostly approximate.** The advice and Study use hand-written charts with no EV (`solver/gto/preflop.py:1-4`). A class-level preflop solver exists (`solver/gto/pf_study.py`, `pf_game.py`). It supports 2–6 players in the browser and 7 natively, equal stacks of 10–250bb, and no ICM. Its results are 2.4–3.0 points off published solves (`docs/research/03` §4). Classic Study can show it as a "Solver" source, and so can Lizard's Study (since 2026-11-03), labelled "Preflop solve (class-level model)".
- **Postflop solves are real, but in an abstracted game.** Heads-up uses DCFR with an exact best-response exploitability (`solver/gto/solver.py:2170-2196`). That number is measured in the abstract game: flop solves bucket the later streets, and the bet menu is small. Three-way spots are solved, 4-way spots use a reduced game, and 5+ players on the flop or turn use betting rules (`docs/research/03` §5, §7).
- **The presolved library is small.** It has 18 heads-up 6-max 100bb lines (9 on the newer river-dealt tree with turn files, 9 on the older tree) and 4 three-way spots on 185 flops each. Lizard's merged library at `/lizard-library/` also has two heads-up 2-max spots, copied from offline builds that are still running: `srp_sb_bb_2max` (1,694 flops so far, planned 1,755) and `lp_sb_bb_2max` (208 so far, planned 552), as of library commit `a11b7127`, 2026-11-05. A launchd job on the owner's Mac publishes new flops every 6 hours, so these counts age; the Library page reads the live ones. Heads-up flops not published yet are solved live. The classic `/gto-solver-library/` has no 2-max spots.
- **There are three grading scales in the classic app, and they disagree.**
  - Practice grades by frequency. Best, Good, Inaccuracy or Mistake; a frequency of 15% or more is fine (`solver/gto/static/practice.js:417-424`, `index.html:1543-1544`).
  - Drills grade by EV on five levels (`drills.js:154-169`).
  - The session analyzer uses mix thresholds of 0.15 and 0.03 (`session.js:528-532`).
- **What Lizard sends.** Its Study request carries players, stack, board, the line and `study: true` (`web/src/features/study/studyState.ts`, `studyRequest`). A spot set up on the Solve page adds `stacks`, `sizes`, `rake` and `rake_cap`, `ante`, `straddle` and `ranges` (`web/src/features/solve/setup.ts`, `setupRequest`); one set up on the Tournaments page adds `payouts`, `field` and `bounties` instead of rake (`web/src/features/tournaments/tournament.ts`, `tournamentRequest`). None of those carries locks, automatic sizing or a preflop solve: Study's own panels send those, each on request (`locks.ts`, `autoSize.ts`, `pfSolve.ts`).
- **Two Lizard over-claims were found by this review and fixed the same day (2026-11-03).** The Practice route summary said "scored by EV loss" (`web/src/app/routes.ts:18`), and the placeholder page listed "EV-loss grading" for Practice. Classic Practice verdicts are frequency-based; only Drills use EV. Both now say so.
